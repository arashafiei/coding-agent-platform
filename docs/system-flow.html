Planner

برنامه‌ریزی

درخواست را به گام‌ها، فایل‌ها و فرمان‌های قابل تست تبدیل می‌کند و ابهام‌ها را مشخص می‌کند.

Coder

تولید کد

برای هر فایل یک worker مستقل با context محدود اجرا می‌شود تا خروجی کوچک‌تر و قابل‌کنترل باشد.

Reviewer

ارزیابی واقعی

بر اساس exit code، stdout و stderr تصمیم می‌گیرد؛ موفقیت بدون اجرای سالم پذیرفته نمی‌شود.

Fixer

اصلاح هدفمند

خطا، فایل‌های فعلی و سابقه تلاش‌ها را دریافت می‌کند و فقط فایل‌های لازم را جایگزین می‌کند.

LangChain

رابط مدل

ChatOpenAI را برای اتصال مستقیم به Luna API و Structured Output فراهم می‌کند.

LangGraph

State Machine

Nodeها، State و شرط انتقال بین Generate، Validate، Repair و END را مدیریت می‌کند.

04 · State & Safety

State، امنیت اجرا و بازیابی

هیچ تصمیم مهمی فقط در حافظه n8n باقی نمی‌ماند؛ وضعیت پایدار در PostgreSQL ثبت و رویدادها به Dashboard push می‌شوند.

PostgreSQL

  • runs وضعیت کلی
  • run_actions تلاش هر Agent
  • code_versions نسخه فایل‌ها
  • execution_results خروجی Sandbox

Redis Streams + SSE

Eventها هم در دیتابیس ماندگارند و هم از Redis به صفحه Run ارسال می‌شوند تا UI بدون refresh به‌روزرسانی شود.

Docker Sandbox

  • Node.js container مستقل
  • شبکه خاموش هنگام تست
  • محدودیت CPU و RAM
  • Timeout و حذف container

Retry قابل‌کنترل

Failure به waiting_retry می‌رود، n8n از wait URL ادامه پیدا می‌کند و سه تلاش واقعی Fixer شامل timeout هم enforce می‌شود.

Watchdog

Action بدون heartbeat از حالت running خارج می‌شود تا Run برای همیشه گیر نکند و امکان بازیابی داشته باشد.

GitHub

نسخه نهایی commit و push می‌شود و SHA آن در گزارش Run و تاریخچه پروژه قابل رهگیری است.

05 · Presentation Script

سناریوی پیشنهادی دمو

این ترتیب، تمام الزامات اصلی پروژه را در یک اجرای کوتاه و قابل‌فهم به استاد نشان می‌دهد.

  1. نمایش این صفحهتوضیح مرز مسئولیت n8n، LangGraph، LangChain، API، Runner و Database.
  2. ساخت پروژه از Dashboardیک Todo List کوچک، in-memory و بدون dependency درخواست کنید.
  3. نمایش Planner و Human-in-the-LoopPlan را بررسی کنید، بازخورد متنی بدهید و سپس تأیید کنید.
  4. دنبال‌کردن Live Stepperتغییر Stateها و Eventهای تهران را بدون refresh نشان دهید.
  5. نمایش اجرای واقعیstdout، stderr، exit code و محدودیت‌های Docker Sandbox را ارائه کنید.
  6. نمایش Fixerدر صورت شکست، انتقال Reviewer → Fixer → Runner را همراه شماره تلاش توضیح دهید.
  7. تحویل نهاییتست سبز، گزارش Markdown، commit SHA و ریپازیتوری GitHub را نمایش دهید.
